# 컨텍스트 ① 사용성(UX) 가이드

> **상태: 초안(논의 중).** 사용자와 논의해 확정하기 전까지 개발 기준으로 쓰지 않는다.

> 적용 순서: ① UX → ② SEO → ③ 디자인 시스템. 이 문서가 "무엇을, 어떤 순서로 보여줄지"를 정하고, ②·③은 이 구조를 전제로 한다.
> 모든 도구 페이지·공통 페이지 작업 전에 읽는다. 충돌 시 이 문서 > 개별 판단.

## 0. 원칙 한 줄
**들어오자마자 숫자 하나 넣고 답을 본다.** 설명·광고·FAQ는 그다음이다.

사용자 가정: 모바일(70%+), 검색으로 바로 도구 페이지에 착지, 한 번 쓰고 나간다, 숫자에 민감하고 의심이 많다.

## 1. 도구 페이지 표준 구조 (위에서 아래 순서 고정)
| 순서 | 블록 | 규칙 |
|---|---|---|
| 1 | Breadcrumb | 홈 > 카테고리 > 도구. 한 줄, 작게. |
| 2 | H1 + 한 줄 설명 | H1은 "OO 계산기". 설명은 "무엇을 넣으면 무엇이 나오는지" 1문장. |
| 3 | **계산기 (입력 + 결과)** | 첫 화면(360×640 모바일)에서 최소 첫 입력칸과 결과 영역 일부가 보여야 한다. |
| 4 | 결과 상세 | 항목별 내역 표, 기준 연도 표시, 공유/복사 버튼. |
| 5 | 광고 슬롯 ① | 결과 상세 **아래**. 입력과 결과 사이에 광고 금지. |
| 6 | 사용법 | 3~5단계 번호 목록. |
| 7 | 계산 방식·근거 | 공식, 요율 표, 출처 링크, 기준일. |
| 8 | 예시 | 대표 입력 2~3개의 결과 표. |
| 9 | 광고 슬롯 ② | 본문 중간 이후. |
| 10 | FAQ | 4~6개, `<details>` 아코디언. |
| 11 | 관련 도구 | 같은 카테고리 3~4개 카드. |
| 12 | 안내 문구 | "참고용, 실제와 다를 수 있음" + 최종 갱신일. |

공통 페이지(홈·소개·약관 등)는 Breadcrumb·H1·본문만.

## 2. 입력 UX
- **기본값을 채워 둔다.** 가장 흔한 값(예: 연봉 4,000만원, 식대 20만원, 부양가족 1명)을 미리 넣고 결과도 미리 보여준다. 빈 폼 금지.
- **실시간 계산**: 입력이 바뀌면 바로 결과 갱신(디바운스 150ms 내외). "계산하기" 버튼은 보조로만 둔다(키보드·스크린리더용 제출).
- 금액 입력:
  - `inputmode="numeric"`, `type="text"` + 천 단위 콤마 자동 표시. `type="number"` 스피너 금지(모바일에서 숫자 키패드·콤마 표시가 나쁨).
  - 입력칸 옆에 단위(원, 만원, 명) 고정 표시.
  - 입력값 아래 한글 읽기 보조: `40000000` → "4,000만 원".
  - 자주 쓰는 값은 칩 버튼으로 빠른 입력(예: +100만, +1,000만 / 0명·1명·2명).
- 정수 개수(가족 수 등)는 −/+ 스테퍼.
- 선택지 2~4개는 세그먼트 버튼, 5개 이상만 select.
- 필드마다 `<label>` 필수, 헷갈리는 필드는 "?" 대신 아래 회색 힌트 한 줄로 바로 설명.
- 입력 순서 = 사람이 머릿속에 가진 정보 순서(가장 확실한 값 → 덜 확실한 값). 선택 항목은 "상세 옵션" 접기 안에.

## 3. 결과 UX
- **핵심 숫자 1개를 가장 크게**(예: 월 실수령액). 그 아래 보조 숫자 1~2개(연 실수령액, 공제 합계).
- 결과 숫자 변경 시 짧은 하이라이트(0.3초, `prefers-reduced-motion`이면 생략).
- 내역 표: 항목 / 금액 / 비율. 합계 행 강조.
- 결과 영역에 기준 표시: "2026년 요율 기준".
- **복사 버튼**: "월 실수령액 2,924,353원 (연봉 4,000만원 기준, 생활계산소)" 형태로 클립보드 복사. 성공 시 토스트 2초.
- **링크 공유**: 입력값을 URL 쿼리(`?salary=40000000&dep=1`)에 반영(history.replaceState). 이 URL로 들어오면 그 값으로 계산된 상태로 열린다. 공유 버튼은 Web Share API 우선, 없으면 링크 복사.
  - 쿼리 페이지는 canonical을 쿼리 없는 주소로 둔다(→ ② SEO).
- 비정상 입력은 결과 영역에 이유를 쓴다("연봉은 0보다 커야 해요"). 숫자 대신 `NaN`·빈칸 노출 금지.

## 4. 모바일·레이아웃
- 기준 폭 360px에서 먼저 설계. 좌우 여백 16px, 가로 스크롤 금지(표는 `.table-scroll` 래퍼 안에서만 가로 스크롤).
- 터치 영역 최소 44×44px, 버튼 간 간격 8px 이상.
- 768px 이상: 계산기 영역은 입력 | 결과 2단 가능. 본문 최대 폭 720~880px.
- 결과가 입력보다 아래에 있는 모바일에서는, 입력 중 결과가 화면 밖이면 하단 고정 미니 결과바(핵심 숫자만)를 띄운다.
- 키보드가 올라와도 현재 입력칸이 가려지지 않게(`scrollIntoView` 불필요한 강제 스크롤은 금지).

## 5. 접근성 (Lighthouse 접근성 90+ 필수, 목표 100)
- 색 대비 WCAG AA: 본문 4.5:1, 큰 글자·아이콘 3:1.
- 모든 인터랙티브 요소 키보드 조작 가능, `:focus-visible` 표시 유지.
- 결과 영역 `aria-live="polite"`로 핵심 숫자 변경 알림(내역 표 전체를 읽게 하지 말 것).
- 오류 메시지는 `aria-describedby`로 입력칸과 연결.
- 색만으로 의미 전달 금지(증가/감소는 ▲▼ 또는 +/− 기호 병기).
- 이미지에는 alt, 장식 아이콘은 `aria-hidden="true"`.
- `prefers-reduced-motion` 존중.
- 글자 확대 200%에서도 레이아웃 깨짐 없이 사용 가능.

## 6. 성능 체감
- JS 없이도 기본값 결과는 HTML에 이미 렌더링(빌드 시 계산). JS는 인터랙션용으로만.
- 도구 페이지 JS 합계 30KB(gzip) 이하 목표. UI 라이브러리 금지.
- 웹폰트 쓰면 1종, `font-display: swap`, 서브셋.
- 광고 슬롯은 높이를 미리 잡아 레이아웃 밀림(CLS) 방지.

## 7. 신뢰
- 숫자 근거를 숨기지 않는다: 요율·공식·출처·기준일을 계산 방식 블록에 명시.
- "참고용" 안내는 결과 바로 아래 한 줄 + 페이지 하단 상세.
- 과장 표현 금지("가장 정확한", "100% 정확").
- 최종 갱신일을 페이지에 표시하고, 요율이 바뀌면 갱신일도 바꾼다.

## 8. 광고와 사용성 (애드센스 정책과 함께)
- 입력칸·버튼·결과 바로 옆/사이에 광고 금지(오클릭 유도로 정책 위반 위험).
- 광고는 페이지당 최대 3개, 첫 화면 광고는 결과보다 아래.
- 광고 슬롯 위에 작은 "광고" 라벨.
- 팝업·전면 광고·자동 재생 금지.

## 9. 문구 톤
- 해요체, 짧게. 전문용어는 처음 한 번 풀어서("비과세액: 세금이 안 붙는 돈, 예: 식대").
- 버튼은 동사: "복사하기", "링크 공유", "초기화".
- 숫자는 천 단위 콤마 + "원", 큰 금액은 "만 원" 병기.

## 10. 도구 추가 시 체크리스트
- [ ] 첫 화면에 입력칸과 결과가 보이는가 (360×640)
- [ ] 기본값으로 결과가 미리 보이는가 (JS 꺼도)
- [ ] 실시간 계산·콤마·한글 읽기·단위 표시
- [ ] 복사·링크 공유 동작, 공유 URL로 열면 같은 결과
- [ ] 오류 입력 시 이유 표시, NaN 없음
- [ ] 키보드만으로 끝까지 사용 가능, aria-live 동작
- [ ] 광고가 입력/결과 사이에 없음
- [ ] 계산 근거·출처·기준일·참고용 안내
- [ ] 관련 도구 3~4개 연결
