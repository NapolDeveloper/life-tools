# 컨텍스트 ② SEO 가이드

> **상태: 초안(논의 중).** 사용자와 논의해 확정하기 전까지 개발 기준으로 쓰지 않는다.

> 전제: ① UX 가이드의 페이지 구조(계산기 → 결과 → 사용법 → 근거 → 예시 → FAQ → 관련 도구).
> 대상 검색엔진: 구글 + 네이버 (+ 다음, 빙). 한국어 단일 언어.
> 정책 확인일: 2026-11-18. 검색엔진 정책은 바뀌므로 6개월마다 재확인하고 이 날짜를 갱신한다.

## 0. 원칙
**검색한 사람의 질문에 이 페이지가 가장 빨리, 가장 정확하게 답한다.** 꼼수(키워드 반복, 숨김 텍스트, 대량 복제 페이지)는 쓰지 않는다. 애드센스 승인과 검색 순위는 같은 기준(쓸모 있는 독자 콘텐츠)으로 움직인다.

## 1. 도구 기획 단계 (만들기 전에)
- 새 도구는 **검색 수요를 먼저 확인**한다: 네이버 검색광고 키워드도구, 구글 키워드 플래너, 구글·네이버 자동완성.
  - 키워드 도구는 사용자 계정이 필요하다. 수치를 확인 못 하면 자동완성·연관검색어로 판단하고 "수요 미확인"으로 기록한다.
- 결과는 `docs/keywords.md`에 기록: 도구 | 메인 키워드 | 보조 키워드 3~5개 | 월 검색량(출처·조회일) | 경쟁 사이트 상위 3개.
- 메인 키워드 1개 = 페이지 1개. 같은 의도의 키워드로 페이지를 두 개 만들지 않는다(자기잠식).

## 2. URL
- 소문자 영문 슬러그, 하이픈 구분, 끝 슬래시 통일: `/salary/`, `/severance-pay/`, `/hourly-wage/`.
- 카테고리 허브: `/money/`(급여·세금), `/life/`(생활), `/date/`(날짜·시간) 등. 도구 URL은 평평하게 두고(카테고리 안으로 넣지 않음), 허브 페이지와 Breadcrumb로 묶는다. → 나중에 카테고리를 바꿔도 URL이 안 깨진다.
- 한 번 공개한 URL은 바꾸지 않는다. 바꿔야 하면 301 리다이렉트(`public/_redirects`, Cloudflare Pages 형식).
- 공유용 쿼리 URL(`?salary=...`)은 canonical을 쿼리 없는 주소로, sitemap에 넣지 않는다.
- 도메인: 커스텀 도메인 필수(애드센스·네이버 소유확인·신뢰도). `*.pages.dev`는 미리보기 전용. www/비www 중 하나로 301 통일, HTTPS만.

## 3. 페이지 메타 (모든 페이지)
| 항목 | 규칙 |
|---|---|
| `<html lang="ko">` | 필수 |
| title | `{메인 키워드} ({연도}년 기준) \| {사이트명}` 형태. 핵심 키워드를 앞에. 한글 기준 약 30자 이내(브랜드 제외). 페이지마다 고유. |
| meta description | 한글 80~120자. "무엇을 넣으면 무엇이 나오는지 + 기준 연도 + 무료/설치 없음". 페이지마다 고유. |
| canonical | 절대 URL, 쿼리 제거, 끝 슬래시 통일 |
| robots | 기본 index,follow. 404·미리보기 환경은 noindex |
| OG | og:title, og:description, og:url, og:type, og:image(1200×630, 도구별), og:locale=ko_KR, og:site_name |
| Twitter | summary_large_image |
| 아이콘 | favicon.svg + 180px apple-touch-icon |
| viewport | `width=device-width, initial-scale=1` (확대 금지 옵션 쓰지 않음) |

- **OG 이미지는 도구별로 빌드 때 자동 생성**(제목 + 핵심 문구 + 사이트명, 디자인 시스템 색 사용). 한국은 카카오톡 공유 미리보기 노출이 중요하다.
- 미리보기(develop) 빌드는 전 페이지 `noindex`. 운영(main) 빌드에서만 index. 환경변수로 분기.

## 4. 본문 구조
- H1 1개 = 메인 키워드 포함 도구명.
- H2 = UX 구조 블록(사용법 / 계산 방식 / 예시 / 자주 묻는 질문 / 관련 계산기). 각 H2 제목에 자연스럽게 보조 키워드를 쓴다("연봉 실수령액 계산 방법"). 억지 반복 금지.
- 첫 문단(H1 아래 1문장)에 메인 키워드와 핵심 답을 넣는다.
- 기본값 결과를 **HTML에 미리 렌더링**한다(JS 없이도 숫자가 보이게). 검색엔진이 "연봉 4천 실수령액" 같은 답을 본문에서 읽을 수 있다.
- 예시 표는 실제 `<table>` + `<caption>` + `<th scope>`.
- 본문 분량 기준: 계산기 외 설명 텍스트 1,200자 이상(사용법·근거·예시·FAQ 합산). 늘리기용 군더더기 금지 — 근거와 예시로 채운다.
- 최종 갱신일을 본문에 표시하고 sitemap `lastmod`·구조화 데이터 `dateModified`와 일치시킨다.

## 5. 구조화 데이터 (JSON-LD)
| 페이지 | 타입 |
|---|---|
| 전체 | `BreadcrumbList` |
| 홈 | `WebSite`(name, url), `Organization`(name, url, logo) |
| 도구 | `WebApplication`(name, url, applicationCategory, operatingSystem: "Any", offers price 0, inLanguage ko, dateModified) |
| 도구 FAQ | `FAQPage` — **구글은 2026년 5월부로 FAQ 리치 결과를 모든 사이트에서 중단**했다. 마크업은 해가 없어 유지해도 되지만 노출 효과를 기대하지 않는다. FAQ 본문 콘텐츠 자체는 계속 쓴다. |
| 계산 방식 | `HowTo` 사용 안 함(리치 결과 중단됨) |

- 구조화 데이터 내용은 화면에 보이는 내용과 일치해야 한다(보이지 않는 FAQ·평점 금지). `aggregateRating` 등 근거 없는 평점 마크업 금지.
- 배포 전 Rich Results Test / Schema Markup Validator로 오류 0 확인.

## 6. 내부 링크
- 모든 도구: Breadcrumb(홈 > 카테고리 허브 > 도구) + 하단 관련 도구 3~4개.
- 본문 설명 중 다른 도구가 필요한 지점에 문맥 링크("퇴직금도 궁금하면 → 퇴직금 계산기").
- 카테고리 허브 페이지: 카테고리 소개 2~3문단 + 도구 카드 목록. 얇은 목록 페이지로 두지 않는다.
- 헤더 내비: 카테고리 허브. 푸터: 소개·개인정보처리방침·이용약관·문의 + 전체 도구(사이트맵 페이지 `/tools/`).
- 앵커 텍스트는 대상 키워드("퇴직금 계산기"), "여기", "바로가기" 금지.
- 고아 페이지(어디서도 링크 안 된 페이지) 금지.

## 7. 크롤링·색인 파일
- `sitemap-index.xml` + 하위 sitemap: 색인할 페이지만, 정확한 `lastmod`. 쿼리 URL·404 제외.
- `robots.txt`: 전체 허용 + Sitemap 절대 URL. 미리보기 환경은 `Disallow: /` 대신 meta noindex 사용(크롤러가 noindex를 읽을 수 있게).
  - 네이버 크롤러(Yeti), 다음(Daumoa), 빙(bingbot)을 막지 않는다.
- RSS(`/rss.xml`): 새 도구·갱신 공지용. 네이버 서치어드바이저에 RSS 제출 가능.
- 커스텀 404 페이지: 검색창 대신 인기 도구 링크 + 홈 링크, noindex.

## 8. 성능 (Core Web Vitals, 75번째 백분위 기준 "좋음")
| 지표 | 목표 |
|---|---|
| LCP | 2.5초 이하 |
| INP | 200ms 이하 |
| CLS | 0.1 이하 |
| Lighthouse (모바일) | Performance 90+, Accessibility 90+, Best Practices 95+, **SEO 100** |

- 광고 슬롯은 `min-height`로 자리를 미리 잡아 CLS 방지.
- 이미지: WebP/AVIF, `width`/`height` 명시, 첫 화면 밖은 `loading="lazy"`.
- 폰트: 시스템 폰트 우선. 웹폰트는 1종, 서브셋, `font-display: swap`, preload.
- 서드파티 스크립트(애널리틱스·광고)는 `async`/`defer`, 첫 화면 렌더링을 막지 않게.

## 9. 신뢰 신호 (E-E-A-T, 애드센스 심사와 공통)
- 소개 페이지: 사이트 목적, 운영자(개인 운영, 이메일 연락처), 계산 방식 검증 원칙, 갱신 주기.
- 도구마다 출처(정부·공공기관 원문 링크)와 기준일.
- 개인정보처리방침: 쿠키·광고(구글 애드센스)·애널리틱스 사용 고지. 입력값은 서버로 전송하지 않음을 명시.
- 오류 신고 경로(문의 이메일)를 도구 하단에 노출.

## 10. 금지 (스팸 정책·애드센스 정책)
- **대량 템플릿 페이지 금지**: "연봉 2,000만원 실수령액", "연봉 2,100만원 실수령액"… 처럼 숫자만 바꾼 페이지를 대량 생성하지 않는다(구글 스팸 정책의 scaled content abuse에 해당할 위험). 이런 롱테일은 한 페이지의 예시 표·쿼리 공유로 처리한다. 예외가 필요하면 사용자 승인 후 페이지마다 고유한 해설이 있는 경우에만.
- 키워드 나열, 숨김 텍스트, 화면과 다른 구조화 데이터, 타 사이트 문구 복제, 의미 없는 AI 생성 장문.
- 클로킹(검색엔진과 사람에게 다른 내용), 낚시성 제목.

## 11. 검색엔진 등록 (사용자 계정·승인 필요 → Claude는 준비만)
1. 구글 Search Console: 도메인 속성 등록(DNS TXT) → sitemap 제출.
2. 네이버 서치어드바이저: 사이트 등록 → 소유확인(HTML 메타 태그, `src/config.ts`에 값 넣으면 head에 출력) → 사이트맵·RSS 제출 → 주요 페이지 수집 요청.
3. 다음 검색등록, 빙 웹마스터 도구(Search Console 가져오기).
- 소유확인 메타 태그 값은 `src/config.ts`의 `VERIFICATION` 상수로 관리.
- 등록·제출은 노출을 보장하지 않는다. 등록 후 2~4주 색인 상태를 확인한다.

## 12. 출시 후 운영
- 월 1회: Search Console·서치어드바이저에서 색인 오류, 노출 키워드, CTR 확인 → `docs/seo-log.md`에 기록.
- 노출은 많은데 CTR이 낮은 페이지 → title/description 개선.
- 매년 1월·7월: 요율·기준값 갱신 + title 연도 + lastmod 갱신.

## 13. 페이지 배포 전 체크리스트

- [ ] canonical 절대 URL, 쿼리 없음
- [ ] H1 1개, H2 구조가 UX 블록과 일치
- [ ] 기본값 결과가 HTML에 렌더링됨
- [ ] JSON-LD 검증 오류 0, 화면 내용과 일치
- [ ] OG 이미지 생성됨(1200×630)
- [ ] Breadcrumb + 관련 도구 + 허브에서 링크됨
- [ ] sitemap 포함, lastmod 정확
- [ ] Lighthouse 모바일 SEO 100, Performance 90+
- [ ] 출처·기준일·갱신일·참고용 안내
